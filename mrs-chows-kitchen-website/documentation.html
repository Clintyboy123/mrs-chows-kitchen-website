1. Getting started

There are two ways to edit: the browser-based admin (needs PHP hosting, recommended for restaurant owners), or by hand in a code editor. Open index.html in any browser to see the site. To edit by hand, open the same file in a code editor (VS Code, Sublime Text, Nova, Notepad++). There is no build step: save the file and refresh the browser.

The site has two responsive pages. index.html is the home page: hero, our story, signature dishes, culture, takeaway & delivery, weekly special, contact with map, reviews and footer. menu.html is the menu page: the full menu (15 categories, 102 dishes in the demo) with category tabs and the order slip. Both share the same top bar, navigation and footer.

3. Changing text

Using the admin? Then make changes there. Hand edits to index.html are replaced the next time someone presses Save & publish. To change the page's structure, edit admin/template.php instead.

Every word on the page is plain text in index.html; search for it and type over it. The restaurant name appears in the top bar, the footer, the map card and the copyright line, so use your editor's Find and Replace for Jade Lantern. Do the same for the address, phone number and opening hours.

Phone links use the tel: format: <a href="tel:+10000000000">. Keep the digits only, with your country code.

The Chinese characters in red seals (味, 鮮, 傳 …) are decorative. Change the character inside <span class="seal">…</span> to use another one.

4. Adding photos

The template ships without photographs. Each photo area shows a tinted placeholder labelled with what belongs there. To add a photo, copy it into assets/img/ and replace the placeholder <div class="ph …">…</div> with:

<img class="ph photo" src="assets/img/your-photo.jpg" alt="Describe the photo">

Compress photos before uploading (e.g. squoosh.app) and keep each under about 300 KB.

Logo: replace <span class="seal">味</span> in the navigation with <img class="logo-img" src="assets/img/logo.png" alt="">. In the footer, replace the seal and name with <div class="logo-card" style="width:220px"><img src="assets/img/logo-full.png" alt="Your name"></div>.

5. Editing the menu

Signature dishes are the <article class="work"> blocks inside <div class="gallery">. The first two are shown large, the rest in rows of four. Copy a block to add a dish; delete one to remove it.

The full menu lives on menu.html. A link such as menu.html#beef opens that category directly (the signature dishes use this). It has a tab per category (<button … data-tab="starters">) and a matching panel (<div role="tabpanel" id="panel-starters">). To add a category, copy a tab and a panel and give both the same new id. Only the first panel has no hidden attribute.

Every Add button carries the dish for the order slip:

<button class="add-round" type="button"
  data-add="kung-pao-chicken"      unique id, letters and dashes
  data-name="Kung Pao Chicken"     name shown on the slip
  data-price="13.90">+</button>   number only; the symbol comes from data-currency

Change the price in both places: the visible <span class="price"> and data-price. If you leave data-price empty, the slip still counts items and shows the total as "—".

The View Special button opens the category named in its data-show-tab attribute (default combos).

About the order slip. Guests build an order and choose collection or delivery; Checkout takes them to the site's own checkout (see Direct online ordering). Payment happens on collection or delivery. To use an ordering provider instead, switch off online ordering in the admin and set the Online ordering link.

Options are attributes on the <body> tag at the top of index.html:

data-prep-time="20–30"Collection estimate (minutes).
data-delivery-time="40–50"Delivery estimate (minutes).
data-cursor="off"Turns off the chopstick cursor.
data-music="off"Hides the music button.
class="no-art"Hides the watercolour landscapes.
class="no-paper"Removes the rice-paper texture.

The music is generated in the browser (a guzheng-style melody on the Chinese pentatonic scale), so there is no audio file and nothing to license. Browsers only allow sound after a visitor taps, so it never plays by itself. The cursor only appears for a mouse; phones and tablets are unaffected. Both respect "reduce motion" settings.

At the top of assets/css/style.css are the design tokens. Change a value and the whole site follows:

--c-red:#B8291E;     seals, buttons, accents
--c-jade:#2E6A4F;    green accents
--c-ink:#1E1B18;     text
--c-paper:#FAF6EE;   page background
--c-forest:#1F3D2E;  footer
--f-display  headings (Noto Serif SC — a Song/Ming face)
--f-body     paragraphs (Noto Sans SC — a Hei face)
--f-brush    Chinese brush characters (Ma Shan Zheng)
--f-script   hand-signed lines (Ma Shan Zheng)

To use your own script font, add an @font-face rule at the top of the stylesheet and put its name first in --f-script. Check the font's licence allows commercial use on websites.

8. Map, ordering link and socials

The map is a Google Maps embed. In index.html find class="map-embed" and change the text after ?q= to your restaurant's name and address (spaces as +). Point both Directions buttons at your Google Maps share link (Google Maps → your place → Share → Copy link).

Social icons are in the footer under Follow; set each href to your page.

9. Publishing

Upload the whole folder (keeping assets/ next to index.html) to any web host: your hosting control panel's file manager, FTP, or a static host such as Netlify, Cloudflare Pages or GitHub Pages (drag and drop the folder).

10. The admin (edit without code)

The template includes a password-protected admin at /admin. Restaurant owners can change every text, the menu, prices, photos, logo, colours and features in the browser, without touching code.

How it works

Content is stored in content/site.php. When you press Save & publish, the admin rebuilds index.html from admin/template.php. Visitors always get a fast static page, and the admin is only used when you edit.

Requirements

  • Hosting with PHP 8.0 or newer (almost every shared host: cPanel, Plesk, Hostinger, Afrihost, Xneelo, SiteGround …). No database needed.
  • The website folder must be writable by PHP (usually already true). If the admin shows "cannot write index.html", set the folder and index.html, content/ and assets/uploads/ to permissions 755 (folders) and 644 (files) in your host's file manager, or ask your host to make them writable by PHP.
  • Free static hosts (Netlify, GitHub Pages, Cloudflare Pages) cannot run PHP. There, delete the admin and content folders and edit index.html as described above.

First use

  1. Upload the whole folder to your host.
  2. Straight away, open https://your-site/admin/ and choose a password (10+ characters). Until a password is set, whoever opens the admin first can claim it, so do this immediately after uploading.
  3. Edit, then press Save & publish. Use Preview changes to see edits in a new tab before publishing.

Photos

JPG, PNG or WebP up to 8 MB. Very large photos are scaled down to 1800 px automatically when the host supports it. Uploaded files are stored in assets/uploads/ under random names.

Security

  • The password is stored only as a hash (content/config.php). Forgot it? Delete that file in your host's file manager and open /admin to choose a new one.
  • Five wrong passwords lock the login for 15 minutes. Sessions end after 2 hours of inactivity.
  • Every form is protected against cross-site requests; uploads are checked to be real images; scripts can't run from the uploads folder (Apache .htaccess included).
  • Content files start with a PHP guard, so opening them in a browser shows nothing. On nginx hosts also deny web access to /content/ in the server config: location ^~ /content/ { deny all; }
  • Always use HTTPS for your site (most hosts include a free certificate).

For developers

The page markup lives in admin/template.php (home) and admin/template-menu.php (menu) and uses e(f($s, 'key')) for each field. To add a field, add it to admin/fields.php and use it in the template. It appears in the admin automatically. After editing the template, press Account → Publish again.

Speed and ordering on phones (1.1)

  • Photos load at the right size. When you publish from the admin, every photo gets small WebP copies (160, 480, 960 and 1600 px wide), and each page tells the browser which to use. A phone downloads about a sixth of what it used to. Photos you upload are also scaled down to 1800 px. This needs the GD image library with WebP, which almost every host has; without it the original photo is used.
  • Textures are images. The rice-paper texture and the watercolour landscapes are small WebP files in assets/img/ (the original vector art is kept in assets/img/art/source/), so scrolling stays smooth on older phones.
  • Calmer on phones. On phones and tablets the slow hero drift, drifting clouds and the frosted-glass blur behind the header are switched off. Desktop keeps them.
  • The map loads when asked. The contact section shows the drawn map with a Show live map button; the Google map (about 1 MB) only loads when someone taps it.
  • The order is remembered. Dishes stay in the order slip when guests move between the home and menu pages, and for 24 hours (stored in their browser only). The order count shows on the home page too, and a Clear order link empties it.
  • Order panel on phones and tablets. Below 1180 px wide the order slip slides up from the bottom bar (View order) instead of sitting below the whole menu.
  • Search and filters. The menu page has a search box and All / Vegetarian / Spicy filters. They use the dish names, descriptions and tags, so nothing extra to set up.

Direct online ordering (1.2)

Replaced in 2.4: orders now come in on WhatsApp. The cart page no longer places orders online. Guests enter their name, choose collection or delivery (with an address for delivery), the time and any notes, then Send order on WhatsApp opens WhatsApp with the whole order typed out to the restaurant's number. There is no payment, no order email and no Orders tab, and order.php has been removed. Set the restaurant's WhatsApp number in the admin. The rest of this section describes the old online ordering and no longer applies.

Guests order straight from the website and pay when they collect or when the food is delivered. No ordering provider or commission is involved.

How an order flows

  1. The guest adds dishes on the menu page and presses Checkout. This opens checkout.html.
  2. They choose collection or delivery, enter their name, phone number, an address for delivery, as soon as possible or a time later today, and an optional note. Then they press Place order.
  3. The order appears in the admin's Orders tab (which checks for new orders every 20 seconds and shows "(1) New order" in the browser tab) and is emailed to the restaurant. The guest sees an order number, and a confirmation email if they gave an address.
  4. In the Orders tab, move each order along: Accept → Mark ready → Complete, or Cancel (call the guest first). Orders older than 90 days are deleted automatically.

Set-up checklist (Hours & ordering → Online ordering)

  • Prices: every dish you want to sell online needs a numeric price in the Menu tab, e.g. 89.00. Ordering stays closed (with a "please call us" message) until at least one dish has a price; dishes without a price can't be ordered online.
  • Order email: where new orders are sent. Orders are always saved in the admin too, so an email that lands in spam doesn't lose an order. Emails go through your host's PHP mail; if they don't arrive, ask your host to enable it, or simply keep the admin open.
  • Collection / delivery, delivery fee and minimum order for delivery.
  • Time zone: pick yours so order times are right (many servers run on UTC).
  • Accept orders switch: turn it off to pause online ordering, e.g. when you're fully booked.

Protection against fake orders and bots

Every order passes these checks on the server:

  • Prices from your menu. The browser only sends which dishes and how many; names, prices and totals are recalculated from your saved menu, so nobody can change a price.
  • Signed form check. Each checkout page gets a signed, time-limited token; orders sent in under 4 seconds (bot speed) or from another website are refused.
  • Hidden spam trap. A field people never see; bots that fill it in are refused.
  • Rate limit. At most 5 orders per visitor per 30 minutes.
  • Cloudflare Turnstile (recommended). A free, privacy-friendly check that's usually invisible. In your Cloudflare account go to Turnstile → Add site, enter your domain, then paste the site key and secret key into the admin. The check then appears above Place order and is verified on the server.

Privacy

Orders hold names, phone numbers and addresses. They're stored in content/orders/, which can't be opened from the web, and are deleted after 90 days. Mention online orders in your privacy notice (in South Africa, POPIA applies).

WhatsApp (1.6)

In /admin → Details → WhatsApp number, enter the number with its country code, digits only (e.g. 27821234567). A WhatsApp button then appears in the phone bottom bar, the contact section and the footer; it opens a chat that starts "Hi …, I'd like to place an order."

The cart page also gets Send order on WhatsApp: it opens a chat with the dishes, quantities, total, collection or delivery and any details the guest has filled in, ready to send. It also shows while online ordering is switched off, so guests can still send their cart. Leave the number empty to hide every WhatsApp button.
